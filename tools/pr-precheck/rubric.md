# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan_fidelity | Plan context's scope, files, exclusions, and deviations against every diff hunk; description against both | Every added, omitted, or changed behavior is accounted for by the plan or explicit deviation notes, and the description accurately states what this diff delivers and leaves out. An honestly recorded shortfall can pass; claiming completion for missing work or silently expanding scope fails. | required |
| observable_test_evidence | Candidate test evidence against the repro steps and plan's test plan | Evidence identifies the original observable behavior and shows the branch's result for the same scenario, with an assertion, output, status, or other concrete outcome that tests the claimed change. Specific narrative results count as evidence; raw logs, numerical exit codes, and separate transcripts for every control are not mandatory. Relevant planned tests have results or explicit limitations. A disclosed remaining failure can pass when the evidence makes the actual outcome clear. A promise to test, an expected result with no run, or only "tests pass" fails. | required |
| repo_checks_recorded | Repo facts' required checks against test evidence and description | Each explicitly requested test or validation command has a reported run and outcome, or an explicit account of why it could not run and the resulting validation gap. A named command or test reported as passing is a result; raw logs are not mandatory. A template's formatting or internationalisation checkbox is a standards ask, not an unstated demand for a separate command transcript. Reported failures are not automatic rejection when honestly explained. Silently skipping required checks or claiming green without naming the checks fails. Do not invent a suite requirement when the repository states none. | required |
| diff_reviewable | Unified diff and commit list, read against the issue and plan | The issue's change can be reviewed directly without unrelated edits, debug leftovers, dead code, commented-out implementations, or avoidable formatting churn obscuring it. Supporting tests and necessary local edits pass. An unrelated cleanup fails even if disclosed. Do not use commit count or diff length alone as a failure. | required |
| stated_standards | Repo facts' PR-template asks and contribution policy, issue-thread direction, and candidate title and description | Every explicitly required template section contains relevant content or a justified N/A, the issue is linked when asked, and any required AI-use disclosure is present. Engage applicable maintainer direction or explain a departure. Do not invent template sections, an AI policy, or a disclosure requirement absent from the repository facts. Boilerplate that leaves a stated requirement unanswered fails. | required |

## Verdict rule

Accept only when every required check passes. One required fail or unclear means reject. Preferred checks, if added later, never change the verdict. Keep an unclear grade visible in the output even though it counts as fail for the verdict. Honest limitations are assessed by the pass conditions above; they are not an exemption for hidden drift, unrelated edits, or ignored stated requirements.
