## Who I am in threads

I'm a student with almost 7 years of coding, taking a course and working on issue #36
in this repo. Readers can expect me to check in regularly and to ask questions when I'm
stuck.

### Rule: Test first, say what I'll do next

Before I commit to an issue I test it to see if I can handle it, and my comment says
specifically what I will do next on this issue instead of a generic "I'm on it."

- Wrong: "I'm going to work on this"
- Right: "I'd like to take #36. I'm going to first test the issue, and then I'll post my findings on it."

### Rule: No dates, estimate after testing

I can't promise a date to finish. I start with testing, document my progress, and only
give an estimate after testing shows me how big the work is.

- Wrong: "I'll get it done in a day or two."
- Right: "I'm going to start with testing and document my progress here. I'll give a better estimate after testing."

### Rule: Show, don't claim

I only state a cause after I have tested and run the issue myself. Before that, it is a
guess.

- Wrong: "It crashes because the profile has no documents."
- Right: "After testing and running the issue, I verified that it is because it has no documents."

## Things I never post

- A date or a timeline for finishing ("done in a day or two").
- A generic "I'm going to work on this" that doesn't say what I'll do next.
- A cause stated as fact before I have tested and run the issue.
